# Ошибки соединения с сервером баз данных

## Симптом: "Не удалось установить соединение с сервером баз данных"

Возникает при работе в клиент-серверном варианте (SQL Server, PostgreSQL),
когда клиент 1С или кластер серверов 1С не могут достучаться до СУБД.

Проверить по порядку:

1. Доступен ли сервер СУБД по сети (ping, telnet на порт СУБД - 1433 для
   MS SQL Server, 5432 для PostgreSQL по умолчанию).
2. Запущена ли служба самой СУБД на сервере.
3. Не исчерпаны ли лицензии/подключения СУБД (для PostgreSQL - параметр
   max_connections).
4. Корректны ли имя сервера и имя информационной базы в параметрах
   подключения (файл настроек кластера серверов 1С или строка соединения
   в файле информационной базы).
5. Нет ли блокировки на уровне сетевого экрана между сервером 1С и
   сервером СУБД.

## Симптом: "Конфликт блокировок СУБД" / deadlock

Платформа 1С сама умеет частично разрешать взаимные блокировки на уровне
собственного менеджера транзакций, но при высокой параллельной нагрузке
(массовое проведение документов, регламентные задания в рабочее время)
возможны deadlock на уровне СУБД. Рекомендации:

- Переносить тяжёлые регламентные операции (закрытие месяца, массовое
  перепроведение, обновление итогов) на нерабочее время.
- Проверить режим управления блокировками информационной базы -
  управляемый режим снижает вероятность конфликтов по сравнению с
  автоматическим на высоконагруженных базах.
- Для MS SQL Server убедиться, что включён READ_COMMITTED_SNAPSHOT.

## Симптом: расхождение времени сервера 1С и сервера СУБД

Может приводить к труднообъяснимым ошибкам сохранения объектов и
таймаутам сеансов. Проверяется синхронизация времени (NTP) между сервером
приложений 1С, сервером СУБД и клиентскими машинами.
