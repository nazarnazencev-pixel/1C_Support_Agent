# Веб-сервисы, HTTP-сервисы и внешние интеграции

## Публикация базы на веб-сервере

Работа тонкого клиента через браузер и работа внешних интеграций через
HTTP-сервисы требует публикации информационной базы на веб-сервере
(обычно IIS или Apache) с использованием расширения 1С для веб-сервера.
Типовые проблемы после публикации:

- База открывается в браузере, но не проходит аутентификацию - чаще
  всего это несовпадение способа аутентификации в настройках публикации
  с фактическим способом входа пользователя.
- HTTP-сервис отвечает 404 - проверить, что имя сервиса в URL совпадает
  с именем, заданным в конфигураторе, и что публикация выполнена заново
  после последнего изменения состава HTTP-сервисов в конфигурации.
- HTTP-сервис отвечает 500 - смотреть текст ошибки в теле ответа (если
  включён вывод подробностей ошибок) или в журнале регистрации
  информационной базы, а не только код статуса.

## Внешние интеграции по REST/SOAP

При интеграции 1С с внешними системами (сайт, склад, CRM, маркетплейс)
через собственные HTTP-сервисы или веб-сервисы типовые причины сбоев:

- Таймаут на стороне вызывающей системы, если операция в 1С выполняется
  дольше, чем ожидает внешняя сторона - решается либо оптимизацией
  обработки запроса в 1С, либо переходом на асинхронную схему
  (постановка в очередь и отдельный запрос статуса).
- Несовпадение форматов данных (например, ожидается JSON, а сервис
  настроен на XML) - проверяется явным тестовым запросом с помощью
  внешнего HTTP-клиента, в обход интегрируемой системы, чтобы исключить
  её как источник проблемы.
- Изменение состава полей во внешнем API без синхронного обновления
  кода интеграции на стороне 1С - типичная причина внезапной поломки
  ранее стабильно работавшей интеграции.
