# Загрузка файлов в чат

Исправление от 14 сентября 2026 года установлено на VPS `46.8.220.47`.

Ранее форма и веб-обработчик принимали только PNG/JPEG до 10 МБ. Дополнительно исходный `FileProcessor` содержал сокращённый список из восьми документов, хотя `DocumentProcessor` перечислял 33 расширения. Теперь обработчики используют общий список, а соответствие списка фронтенда бэкенду проверяется тестом.

## Форматы

- Текст: TXT, MD, MARKDOWN, LOG, CSV, TSV, JSON, XML, HTML, HTM, CSS, YAML, YML, INI, CFG, CONF.
- Документы: DOC, DOCX, PDF, RTF, ODT, EPUB.
- Таблицы: XLS, XLSX, XLSM, XLT, XLTX, ODS.
- Презентации: PPT, PPTX, PPS, PPSX, ODP.
- Изображения: PNG, JPG, JPEG, WebP.

Лимит документа — 40 МиБ, изображения — 15 МиБ. Nginx и middleware допускают multipart-запрос до 41 МиБ, а обработчик отдельно проверяет точный размер вложения. Пустые файлы отклоняются. Ограничения соответствуют опубликованным [ограничениям GigaChat](https://developers.sber.ru/docs/ru/gigachat/guides/working-with-files); прежние 50 МБ в исходнике были предварительным значением с TODO.

## Подготовка к GigaChat

Список расширений приложения шире прямой поддержки API, поэтому простого изменения поля `accept` недостаточно.

| Входной формат | Передача в GigaChat |
| --- | --- |
| DOC, DOCX, PDF, EPUB, PPT, PPTX, XLSX | Исходный документ |
| Текстовые форматы | TXT в UTF-8; также распознаются UTF-16 с BOM и Windows-1251 |
| RTF | Извлечённый текст в TXT |
| ODT, ODS, ODP | Текст из `content.xml`, включая текст ячеек и названия листов/страниц |
| XLS, XLT | Названия листов и значения ячеек в табличном TXT |
| XLSM, XLTX | Исходный контейнер передаётся с расширением XLSX |
| PPS, PPSX | Исходный контейнер передаётся с расширением PPT/PPTX |
| WebP | PNG |

При извлечении текста оформление, диаграммы и встроенные изображения не сохраняются. XLS читается по сохранённым значениям ячеек; формулы не пересчитываются. Пароли и повреждённые файлы могут препятствовать чтению. Это не выполнение офисных макросов. После преобразования размер проверяется ещё раз. Полная совместимость всех вариантов офисных контейнеров с внешним API не подтверждена реальными запросами.

## Проверки

- 86 Python-тестов: весь список на входе HTTP-обработчика, обратная связь, преобразование текстовых форматов, RTF, OpenDocument, настоящий XLS/XLT, преобразование WebP, границы размера и пустые файлы.
- 5 тестов фронтенда и 10 браузерных сценариев: выбор TXT/DOCX/ODS/XLS, включая отсутствие MIME-типа и расширения в верхнем регистре.
- Реальные запросы через Chrome на VPS: TXT, DOCX, YAML и XLS дали HTTP 200. GigaChat вернул код ошибки 7421 из каждого тестового файла; для XLS — 7421.0 как числовое значение ячейки.
- Для DOCX проверено отображение вложения на экране шириной 390 пикселей: горизонтального переполнения и ошибок JavaScript нет.
- Для остальных форматов проведены локальные проверки приёма/преобразования; успешная обработка всех реальных разновидностей этих файлов внешним GigaChat не заявляется.
